# Architecture

The app communicates with SREF Viewer's public read-only API. It does not embed the web page, run the extractor, or modify the server. Each network request snapshots the chosen HTTPS server; changes cancel/retire old UI work and partition the cache and alert ledger.

`WeatherRepository` owns the forecast/geocode/history/warning contract. Its shared bounded transport explicitly rejects redirects, enforces response-size and connection/read/total time bounds, and disconnects sockets on cancellation. Building forecasts are polled with a fixed total deadline; useful partial observations can render while model extraction finishes. A successful complete result becomes an offline snapshot. Background alerts always use an explicit live fetch, never an invisible cached fallback. `RainNowcastRepository` separately validates the deployed minute-radar contract, scan freshness and coverage; typed liquid-equivalent rates and phase-aware intensity scales are separate from hourly accumulation. Legacy reflectivity thresholds are used only when rates are absent. The process-wide `RainRequestCache` coalesces UI/worker/watch requests and retains successful and failed results for at least two minutes without refreshing their data timestamps.

`WxViewModel` owns screen state. Place changes cancel outstanding requests and use a monotonically increasing generation guard so a slow response cannot repaint a newer location. Background work is isolated from UI navigation and reloads persisted settings immediately before publishing a notification.

`AlertScheduler` uses unique network-constrained WorkManager requests with a minimum 15-minute cadence, backing off to 30 minutes only on complete fresh dry guidance when no official or hourly alerts are enabled. WorkManager setup runs off the main thread. `WeatherAlertWorker` and a user-started `RainWatchService` share `WeatherAlertEngine`, which enforces target opt-in, permissions, freshness, settings consistency, location age, quiet hours and persisted duplicate suppression. Background location is a separate opt-in from foreground use. With platform permission, `BackgroundLocation` resolves a recent native fix during a scheduled check; it never silently falls back to a stale stored point. Denied or unavailable current location does not stop saved-place checks. The optional Rain watch is a one-hour, non-restarting foreground data-sync session with a persistent Stop notification and a two-minute active/five-minute dry cadence; it never obtains new location fixes. No permanent service is started. All timing and location limits are visible in the app.

The persisted notification ledger is isolated by the full normalized backend base URL and place area. Its live-precipitation latch spans type changes through a single spell. It rearms on an observed wet→clear transition, or on two distinct fresh clear scans after an unobserved prediction’s known validity window expires. Unknown/stale/errors cannot count as dry. Synchronous ledger persistence before OS notification posting prefers avoiding duplicates; a process crash at that narrow boundary can lose a notice, so delivery is not exactly-once.

UI renderers consume typed data in original NOAA units (Fahrenheit, mph, inches). Unit conversion happens at presentation. Forecast timestamps use the forecast place's IANA time zone; quiet hours deliberately use the device zone. Missing values remain missing. Native MapLibre owns map gestures, rendering and its bounded tile cache; Compose owns the controls.

The source's temperature palette is computed in OKLCH and converted to sRGB in the app. Fonts are bundled, charts render with Compose Canvas, and lists are lazy. Source history and hourly/daily endpoints remain separate so optional data does not block the first forecast paint.

`NativeRadarNowcast` renders bounded Mercator-resampled bitmaps on a background dispatcher using the server's MRMS reflectivity, mean-motion and palette PNGs. The native map receives them through an `ImageSource`; it does not embed a webpage or run JavaScript. Memory and response sizes are capped. A scan without motion or fresh coverage is not presented as a valid extrapolation.
